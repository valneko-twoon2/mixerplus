# MixerPlus harness

- `AGENTS.md` holds the shared instructions. There is no `CLAUDE.md`.
- `.agents/skills/` is canonical and `.claude/skills/` mirrors it byte for byte.
  Do not hand-edit mirrors. After editing `.agents/skills/`, run
  `pwsh -File scripts/sync-harness.ps1`; `-Check` detects drift. Delete obsolete
  mirror files explicitly when a skill is removed.
- `.codex/` contains only config and hooks; `.claude/settings.json` adapts the same
  Stop hook. Both are generated by `sync-harness.ps1`. There are no rules
  directories under `.agents/` or `.codex/`, and no skills directory under `.codex/`.
- Git stores normalized LF blobs; working-tree text must be CRLF, except the
  LF-only `.githooks/` launchers that `.gitattributes` documents. Do not use
  `core.autocrlf` as a substitute for attributes. Fix endings with
  `pwsh -File scripts/check-line-endings.ps1 -Fix`.
- `THIRD-PARTY-NOTICES.txt` is generated from the release dependency closure and is
  embedded in the application as its Credits list. After any change to
  `src/Cargo.toml` or `src/Cargo.lock`, run `pwsh -File scripts/update-notices.ps1`
  and commit the result; validation fails while it is stale. Do not hand-edit it.
- Local hooks are guardrails, not an immutable security boundary. Do not claim
  they prevent `--no-verify`, force a human to commit, or replace server policy.
